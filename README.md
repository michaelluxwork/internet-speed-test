# Замер скорости скачивания

Консольный скрипт на Node.js: принимает URL, выполняет 10 последовательных GET-запросов и полностью читает каждый ответ перед следующим запросом. Выводит среднее время запроса, общий объём полученных данных и скорость скачивания. Внешних зависимостей нет.

## Запуск

Нужен **Node.js 22 или новее**. Скачайте репозиторий и откройте терминал в его папке:

```sh
node speed-test.mjs "https://example.com/large-file.jpg"
```

Замените адрес на прямую ссылку на доступный файл, желательно размером несколько мегабайт. Адрес в примере — шаблон, наличие файла по нему не предполагается. Поддерживаются HTTP и HTTPS; стандартные перенаправления обрабатывает `fetch`.

## Проверка на реальном файле

18.11.2026 выполнен запуск на Node.js v22.23.2 с публичным архивом заголовков с официального сайта Node.js:

```sh
node speed-test.mjs "https://nodejs.org/dist/v22.14.0/node-v22.14.0-headers.tar.gz"
```

Фактический вывод, код завершения — 0:

```text
Выполнено запросов: 10
Среднее время запроса: 2385.65 мс
Общий объём данных: 87713440 байт
Скорость скачивания: 29.41 Мбит/с
```

Это результат одного запуска до выбранного сервера, а не ожидаемая скорость для любого подключения. При повторении время и скорость будут другими. За эту проверку получено около 87,7 МБ данных: архив скачивается 10 раз. Сетевой прогон дополняет автоматические тесты ниже.

## Расчёт и единицы

- Время каждого запроса измеряется через `performance.now()` от начала `fetch` до полного чтения тела, включая ожидание сервера и перенаправления. Среднее время = сумма времени 10 запросов / 10, единица — миллисекунды.
- Объём = сумма `byteLength` всех прочитанных частей тела за 10 запросов, в байтах. HTTP-заголовки и служебные сетевые данные не учитываются; `Content-Length` для расчёта не используется. Файл не сохраняется, тело читается потоком.
- Скорость = общий объём в байтах × 8 / суммарное время запросов в секундах / 1 000 000. Единица — **Мбит/с**, где 1 Мбит = 1 000 000 бит. Это отношение суммарного объёма к суммарному времени, а не среднее отдельных скоростей.

Скрипт просит сервер не сжимать ответ (`Accept-Encoding: identity`). Если сервер всё же пришлёт сжатый ответ, `fetch` распакует его: в таком случае счётчик покажет объём распакованного тела, а не объём в сети. `Cache-Control: no-cache` просит перепроверять кэш, но не гарантирует отсутствие кэширования у сервера/CDN. Node.js может повторно использовать соединение между запросами.

Это оценка скорости получения данных с выбранного адреса: на результат влияют размер файла, задержка, сервер, CDN и текущая нагрузка сети. Она не подтверждает максимальную пропускную способность подключения. Всего скачивается 10 копий файла.

## Ошибки

На один запрос отводится 30 секунд, включая чтение тела. Неверный URL, сетевой сбой, таймаут или HTTP-ошибка останавливают запуск: сообщение выводится в stderr, код завершения — 1. Итог по неполной серии не выводится. Пустой успешный ответ допустим и даёт 0 байт и 0 Мбит/с.

## Проверка

```sh
node --test speed-test.test.mjs
```

Тесты используют локальный HTTP-сервер: проверяют 10 запросов без перекрытия, чтение отложенной части тела, точный объём и формулу, HTTP-ошибку, обрыв тела, таймаут, пустой ответ, перенаправление и неверный адрес. Интернет для тестов не нужен.
